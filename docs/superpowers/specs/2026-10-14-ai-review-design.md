# AI 复审（会员专属·千问 VL 二次复筛）设计文档

> 状态：设计已确认，待评审 → 进入实施计划。**本文档不含任何已落地代码**，是对"要建什么、怎么建、边界在哪"的完整约定。
> 日期：2026-10-14

## 1. 一句话目标

对**待确认库**里本地引擎拿不准的边缘图，用云端多模态大模型（阿里云**通义千问 VL**）再判一遍，产出**只读建议**（人数四分类 + 内容型瑕疵），在专门的"前后对比"界面里让**会员**逐张复核或一键批量采纳；**AI 不自动改任何分类/标签/入库**，用户点采纳才通过软件既有的重判通道生效、且可撤回。

## 2. 为什么这么做（背景与已锚定的决策）

- 现有引擎是**完全本地离线**（PyInstaller 打包的 Python + ONNX/mediapipe），这是产品卖点，**不动它**：本地照常筛，没网也能用。
- 待确认恰恰是本地规则判"存疑/中置信"的边缘图，人工成本高，交给更强的图像理解模型复判能省大量人工。
- 会员门控复用现成体系：`auth.ts` 已连 `https://st.uxuuu.cn/api/client`，`isMember`（`membership.level != 'free' && !is_expired`）在 main 与 renderer 都有；积分体系已存在（1 张图 1 积分、会员免扣）。

**决策汇总（均经用户拍板）：**

| # | 决策 | 取值 |
|---|------|------|
| D1 | 模型放哪 | 云端，**客户端直连千问 VL**；图片**不经过用户自己的服务器** |
| D2 | 凭证怎么给 | 用户后端**下发千问 API-KEY**，客户端直连；出事后台**换 key** |
| D3 | 领 key 接口谁写 | **契约本文档给，用户后端实现**（本仓库无服务端代码） |
| D4 | 每张模型费谁出 | **用户平台出**（会员免费用） |
| D5 | 复审结果用法 | **只给建议 + 采纳**，AI 绝不自动改库 ，需要用户自己确认采纳才改标签改分类改库|
| D6 | 采纳写库方式 | **复用 `ReviewPanel` 既有提交通道**，不另开写库后门 |
| D7 | 复审范围 | 人数四分类（单人/多人合拍/多人混合/无人物）＋ 内容型瑕疵（闭眼/半截头/表情崩坏） |
| D8 | 画质型（模糊/曝光/黑白） | **AI 不碰**（压缩小图判不准、本地已判好） |
| D9 | 如何运行 | AI复审时只针对待确认库 不影响其他功能，待确认面板在AI复审时 该界面是弹出显示如： 进度 AI复审中请稍后  共多少张 ，当前第几张  大约用时多少  ，进度当前真正审核 xxxxx.jpg图片  ，然后加个进度条 ，检测期间 整个待去人界面不可其他操作，只显示弹窗复审过程面部 背后透明度20% ⚠（2026-10-14 定稿：全局后台跑不冻结软件，仅待确认页内弹独占进度弹窗，见 7.3） |

> **凭证风险如实记录**：D2 下发的是长期 API-KEY，运行时会躺在用户机器内存里，可被扒取；后台换 key 只能"事后止损"，堵不住换之前的窗口，也不天然卡会员。已尽力压低：① 领 key 接口服务端**只认已登录+会员**、② 按用户/IP **限频**、③ 定期+事后换 key。若日后要彻底藏 key，唯一替代是"服务器瘦代理转发"（图片需过一道后端），本期不做。

## 3. 整体数据流

```
本地筛选跑完（离线引擎，不变）
   │  待确认图 status=done, category=review 或 flawLevel=mid
   ▼
[会员 && 顶部"AI复审"开关 ON && 已同意隐私]
   │
   ├─ 1) 客户端向用户后端领 key： POST ai_review_key.php（Bearer token）
   │        服务端校验会员 → 返回 { api_key, endpoint, model, ttl }（只认会员、限频）
   ├─ 2) 逐张（并发可控）：从磁盘取图 → 解码 → 压到长边≤1024 JPEG(q≈82)
   │        → base64 → 直连千问 VL：固定 system+user 提示，要求回严格 JSON
   ├─ 3) 解析 JSON → 映射成"建议"（人数维度 + 瑕疵应有/应无 + reason）
   │        → 写入该图 images.ai_review（只读建议，不动 tags/category）
   ▼
全部跑完 → 进入待确认页弹"复审小结"
   │
   ├─ [逐张复核] → 前后对比界面（只列差异项）→ 采纳/改一改/跳过
   └─ [全部采纳] → 批量走 D6 通道提交（整批可 ↩ 撤回）
   ▼
采纳时：removeDimTag / addDimTag / correctImage / moveIds（与手动重判完全一致）
```

## 4. 后端领 key 接口契约（用户后端实现）

> **接口详细契约以 `2026-10-14-ai-review-api-contract.md` 为准**（已据此拆为**两个**接口：`ai_review_key.php` 领 key + `ai_review_usage.php` 分批上报用量）。因为图片不经过后端，服务端看不到复审张数，需客户端带一个后端签发的 `session_id` 回报 `used_today`，才能硬卡每日上限与核算成本。下文为早期单接口草稿，保留作背景。

沿用现有风格（`*.php`、`Authorization: Bearer <token>`、返回 `{ code, message, data }`）。

**Endpoint：** `POST https://st.uxuuu.cn/api/client/ai_review_key.php`

**请求头：** `Authorization: Bearer <token>`（复用现有登录 token），`Content-Type: application/json`

**请求体：** `{ "scope": "review" }`（预留，便于以后按功能发不同 key）

**返回：**
```jsonc
// 200 会员有效
{ "code": 200, "message": "ok", "data": {
    "api_key": "sk-**********",           // 千问 DashScope API-KEY
    "endpoint": "https://dashscope.aliyuncs.com/compatible-mode/v1", // OpenAI 兼容端点
    "model": "qwen-vl-max",               // 可由后端改，客户端不硬编码
    "ttl": 600,                            // 建议缓存秒数；到期客户端重新领（非 key 真实有效期）
    "daily_limit": 500,                    // 该会员今日复审张数上限（服务端权威）
    "used_today": 132                       // 今日已用（服务端统计，用于客户端展示/拦截）
}}
// 403 非会员/已过期
{ "code": 403, "message": "AI 复审为会员专属功能" }
// 429 触发限频
{ "code": 429, "message": "操作过于频繁，请稍后再试" }
// 401 token 失效（与现有 auth 口径一致）
{ "code": 401, "message": "登录已失效，请重新登录" }
```

**服务端职责（用户侧实现要点，非本仓库）：**
1. 校验 token 有效 + 会员未过期，否则 403（这是"非会员怎么都无法复审"的真正闸门，客户端界面锁只是体验层）。
2. 对该接口按 用户ID + IP 限频（防脚本疯狂领 key）。
3. 记录每次下发（谁、何时）用于成本核算与异常排查。
4. 支持后台**随时换/吊销** `api_key`；客户端只透传，不内置任何默认 key。

**客户端约束：** 拿到的 `api_key` 仅存内存、随用随取，**绝不写磁盘 / 不写日志 / 不进崩溃上报**；`ttl` 到期或收到 401/403 即清缓存并停复审。

## 5. 千问 VL 调用规格（客户端）

- **模型：** 后端 `model` 字段决定（默认 `qwen-vl-max`，可切 `qwen-vl-plus` 省钱）。客户端不硬编码。
- **端点：** OpenAI 兼容 `chat/completions`，`Authorization: Bearer <api_key>`。
- **图像准备：** 从磁盘原图（复用 `orientedSharp` 做 EXIF 方向纠正）解码 → 缩放至**长边 ≤ 1024px** → JPEG **quality ≈ 82** → base64 data URL。RAW/HEIC 等不可直接解码格式走现有解码兜底管线；若解码失败，该图标记"无法复审"跳过（不计费、不写建议）。
- **提示（要求严格 JSON，`temperature=0`）：**
  - system：你是严谨的摄影选片助手，只输出 JSON，不解释。
  - user（含图）：判断：①画面人数归属= single/group/mixed/none 之一（group=多人面向镜头摆拍合影；mixed=多人但有路人/接亲等非摆拍；single=一个完整人，宠物不算；none=无主体人物）；②是否存在以下**内容型**瑕疵：闭眼（含眯眼/半睁，低头远看像闭眼但不闭的不算）、半截头（仅主要人物头部被裁，远景小头不算）、表情崩坏（露牙大笑/仰头/狰狞等）；各给 true/false。
  - 期望输出：
    ```json
    {
      "person": "group",
      "flaws": { "eyes_closed": false, "half_head": false, "expression": false },
      "reason": "四人并排均面向镜头，站位齐整"
    }
    ```
- **健壮解析：** 容忍模型包 ```json 代码块 / 前后废话 → 抽取第一个 `{...}`；`person` 不在枚举内、或 JSON 解析失败 → 该图判为"复审失败"（不写入错误建议、可重试）。

## 6. 数据结构变更

**6.1 新列 `images.ai_review`（一次性迁移，与 `engine_sig` 同款 `try{ALTER}catch{}` 幂等模式）**
存"只读建议"，**与 `tags`/`category` 正交**，绝不参与 `computeCategory`/`flawLevel`/导出判定。JSON：
```jsonc
{
  "sig": 5,                 // 产出建议时的引擎签名（便于日后规则升级时判失效）
  "model": "qwen-vl-max",
  "at": 1728880000000,      // 生成时间
  "person": "group_photo",  // 建议人数维度（PERSON_DIMS 之一）；与现状相同则仍写入便于展示"一致"
  "flaws": {                // 仅内容型三项，值为 true/false（建议应有/应无）
    "eyes_closed": false, "half_head": true, "expression": false
  },
  "reason": "四人并排均面向镜头"
}
```
- **失效规则**：任何重扫（`resetStaleForRescan` / 手动重筛）在 `updateDetectResult` 覆盖该图结果时，**顺带清 `ai_review=NULL`**（建议基于旧判定，重扫后不作数）。采纳/跳过/驳回也把该图 `ai_review` 置空。
- 维度键名以实现时 `DIMENSION_LABELS`/`BAD_DIMENSIONS` 为准（闭眼=`eyes_closed`、半截头=`half_head`、表情崩坏=对应键，实施计划里钉死）。

**6.2 `AppSettings` 新增可选字段（落 `settings` 键值表，向后兼容、不回填）**
```ts
aiReviewEnabled?: boolean   // 顶部开关（会员可开；持久化上次选择）
aiReviewConsent?: boolean   // 首次开启的隐私授权是否已同意
```
> 每日上限/已用不长期存本地，以接口返回的 `daily_limit`/`used_today` 为准（服务端权威），客户端仅用于展示与前置拦截。

## 7. 客户端交互与界面

**7.1 门控与入口（复用 `isMember`）**
- **侧栏"待确认"标题后**加灰色小字标签 `AI复审`：
  - 非会员：`text-fg3` 灰字，`title="会员专属功能"`；点击 → 打开会员中心（`showMember`）。
  - 会员：正常色，`title="开启后待确认会自动二次复审"`；点击 → 开/关 `aiReviewEnabled`。
- **顶部筛选目录前**加 `AI复审` 开关按钮：
  - 非会员：灰色禁用样式按钮，点击 → 打开会员中心。
  - 会员：真开关（开=`aiReviewEnabled`），关闭态文案提示"关闭后可在待确认手动复审"。
- **会员中心 `MemberCenterDialog`**：会员特权列表加一行"支持 AI 复审 · 待确认自动二次复判"（千问费由平台承担、准确率不保证、只给建议不自动改动）。

**7.2 首次授权弹窗（开启开关且 `!aiReviewConsent` 时）**
标题"开启 AI 复审"，正文两条：
1. "复审会把待确认照片压缩后上传到**阿里云**做图像识别，用于返回判定建议。"
2. "**AI 复审只给建议，不自动改分类、不入库、不覆盖标签——需要你点采纳才生效，且可随时撤回。**"
按钮：[同意并开启] [取消]。点同意写 `aiReviewConsent=true`。

**7.3 触发与运行形态（全局后台任务 · 待确认页内显示独占进度弹窗）**
> **2026-10-14 澄清定稿**：复审本身是**全局后台任务**——不冻结整个软件，你在别的页面照常操作、任务在后台继续跑；但**当你停在/进入“待确认”页时，该页弹一个独占的进度弹窗**，挡住照片查看与操作、只能看进度等待，切去别的页面即不受它挡。
- **触发**：① 顶部"自动 AI 复审（待确认类）"开关 ON && 会员 && 已授权 && 今日额度未用尽 && **待确认库有照片** → **本地筛选一结束即在后台自动开始**（待确认为空则跳过、不跑）；② 会员也可在待确认页点"现在复审"随时手动补跑；③ 开关旁"这次不复审"可临时取消本次自动。
- **运行形态（全局、不冻结软件）**：任务在**后台跑**，切到交付库/合影/别的分类、筛选、导出都不受影响、任务照跑；**只有“待确认”这一页**在复审进行中被进度弹窗占住。
- **待确认页内：独占进度弹窗**（仅当你当前停在待确认页、且复审还在跑时显示）——挡住该页的照片与判定操作，只能看进度、等待；内容逐张实时刷新：
  ```
  AI 复审中，请稍候
  共 40 张 · 当前第 12 张 · 预计还需 约 1 分 20 秒
  正在复审：CHEN9581.jpg
  [▓▓▓▓▓▓░░░░░░░░] 30%
  [ 停止复审 ]
  ```
  切去别的页面时这个页内弹窗随之不可见（但后台任务不停），回来仍在跑就继续显示。
- **软件级进度（非阻塞）**：在别的页面时，顶部进度区给一条轻量小字 `AI 复审中 12/40 · CHEN9581.jpg`（与"重复/连拍聚类"同款），不挡操作，跑完自动消失。
- **停止**：待确认弹窗或顶部指示旁的 **[停止复审]** 均可点；停下后已完成图的 `ai_review` 建议保留、未跑的不再跑；可随时再手动开始。
- **完成**：弹窗/指示消失，把侧栏"待确认"上的 `AI复审` 标签点亮成提示态（如"有 N 张建议"）；进待确认页再按 7.4 看小结 / 逐张复核。

**7.4 进入待确认 → 小结弹窗（非强制：后台跑完不自动弹，进待确认页才弹）**
```
AI 复审完成
共复审 40 张，其中 23 张有不同意见
  建议改人数归属 12   建议删瑕疵 9   建议加瑕疵 6
[ 逐张复核 ]   [ 全部采纳这 23 条 ]   [ 以后再说 ]
```
"以后再说"关闭即可，建议仍存 `ai_review`，下次进待确认可再弹或从每图标记进入。

**7.5 逐张复核·前后对比界面（核心，长在同一套 `ReviewPanel` 版式上）**
原则：**只把"AI 与现状不一致"的行拎出来用箭头强调，一致项收成一句安静小字**——不堆一排带边框彩色标签（用户明确反对）。

```
┌─────────────────────────────────────────────────────────┐
│ [缩略图]   人数    多人混合照  →  多人合拍照              │
│  (大图)            AI：四人并排均面向镜头，站位齐整      │
│             闭眼    有·存疑  →  无                        │
│                   AI：两只眼睛都是睁开的                  │
│             —————  其余项 AI 与现状一致  —————           │
│                                                          │
│ [采纳这张] [改一改] [跳过]            ←  下一张 →        │
└─────────────────────────────────────────────────────────┘
```
- 每行 = `现状 → AI建议`；变化项的建议值用品牌色强调 + AI 一句话 `reason`；无变化项不进列表。
- **[采纳这张]**：等价于按该建议触发 D6 通道（见 7.6），提交后 `ai_review` 置空、图离开待确认（或按建议落到对应栏）。
- **[改一改]**：打开**现成 `ReviewPanel`**，把 AI 建议**预填**成它的选择（人数单选已选中、瑕疵三态已按建议设好），用户微调再手动提交——复用而非重造。
- **[跳过]**：清该图 `ai_review`（本张不采纳，下次复审可再产生）。

**7.6 采纳的写库（D6，复用现有通道，绝不新增直改库路径）**
对一张图，把建议翻译成与手动重判**完全相同**的调用序列：
1. 瑕疵：`flaws[d]==false 且现状有该标签` → `removeDimTag([id], d)`；`flaws[d]==true 且现状无` → `addDimTag([id], d)`。
2. 现状"中置信存疑"的瑕疵若建议保留 → 走 `correctImage(action:'correct', origDim)` 提为高置信（与 ReviewPanel 第 2 步一致）。
3. 人数：`person != 现状人数` → `moveIds([id], person)`（互斥换人数标 + `category_by='user'`）。
4. `refreshImagesFor` / `refreshCounts` 刷新。
> 全部经现有 IPC，自动进顶栏 ↩ 撤回栈；**批量采纳**逐张执行同一序列，包在一个"本次采纳 N 张"的分组里，↩ 可整体撤回（若现撤回栈不支持分组，则逐张可撤，实施计划确认）。

## 8. 边界与失败处理

| 场景 | 行为 |
|------|------|
| 无网络 / 离线 | 领 key 或调用失败 → 不写建议；toast"需联网，AI 复审已跳过"；不阻断本地筛选结果 |
| 领 key 返回 403/401 | 会员失效/token 过期 → 停止复审、清内存 key、引导重新登录/开通 |
| 每日额度用尽 (`used_today>=daily_limit`) | 到上限即停，提示"今日 AI 复审额度已用完，明天再来"；不自动降级为本地强判 |
| 千问调用超时/报错 | 单图重试 1 次；仍失败标"复审失败"，不计费失败、可在小结里"重试失败的 N 张" |
| 模型返回非法 JSON / 越界枚举 | 判"复审失败"，绝不写入猜测值 |
| 图片无法解码（损坏/超大 RAW） | 跳过、标"无法复审"、不写建议 |
| 复审期间用户关了开关 / 登出 | 立即停止在途请求，已写入的建议保留（下次可复核），未跑的不跑 |
| 重扫 / 引擎签名变更 | 该图 `ai_review` 置空（建议随旧判定作废） |
| 待确认图已被手动处理（离开待确认） | 采纳前二次校验现状，冲突则跳过该张并提示 |
| 采纳后想反悔 | 顶栏 ↩ 撤回（与手动重判同等） |

## 9. 隐私 / 成本 / 准确率红线

- **隐私**：图片上传至阿里云识别，首次必须显式授权；用户后端不中转图片、不长期留存（只发 key）；客户端不落盘 key。
- **成本**：会员免费 = 平台逐张付费 → 服务端**每日上限**兜底（默认 500 张/天，可在后端调），压小图降 token，失败不计费。
- **准确率**：**不承诺 99.9%**（待确认本就是边缘图，模型也会错）。正因"只给建议 + 人工采纳"，**结构上不可能把对的图自动改错**，守住"只能进步不能回归"。

## 10. 分期

- **一期（本设计）**：门控 UI + 授权 + 自动/手动复审 + 小结 + 逐张对比 + 采纳（复用通道）+ 全部采纳 + 失败处理。范围=四分类 + 闭眼/半截头/表情崩坏。
- **二期（可选）**：高置信自动归档（需模型回置信度 + 定阈值）、本地开源视觉模型离线可选路径。

## 11. 验收 / 测试策略（决策正确性靠"结构不回归"而非"模型全对"）

1. **门控**：非会员点开关/标签 → 只跳会员中心、拿不到 key、绝不触发复审；伪造"会员态"过不了服务端 403。
2. **非破坏性**：跑完复审后、采纳前，断言 `tags`/`category`/`engine_sig` **一字未变**，只有 `ai_review` 被写。
3. **采纳等价性（关键回归基准）**：对同一批图，脚本分别走"AI 建议采纳"与"手动在 ReviewPanel 选同样结果提交"，比对最终 DB 状态**逐字段一致**（仿合影那次做的忠实复刻基准）。
4. **失效**：重扫后 `ai_review` 清空；登出/关开关停在途。
5. **失败注入**：断网 / 返回非法 JSON / 403 / 额度尽 → 均有兜底、无脏写、可重试。
6. 端到端在开发版用一个真实待确认子集跑一遍，人工核对对比界面呈现与采纳落点符合预期后方算完成（**未端到端验证前不报"已修好"**）。
